#flashcards/automation/cicd
***
[[Символические ссылки (Мягкие, Симлинк)|Симлинк]] - самый популярный способ реализации [[ZDD (Zero Downtime Deployment)|ZDD]] без [[Даунтайм (Downtime)|даунтайма]], а также [[Rollback (Ролбэк, Откат) в CD|ролбэка]] без сложных [[Docker]]-[[Кластер|кластеров]].
***Проблема.***
Если во время [[Деплой|деплоя]] скачивать в папку проекта на [[Продакшн (Prod, Production)|прод]] новую версию кода, то, например, сайт, может сломаться на какое-то время.
***
***Устройство.***
1. В папке `/releases/` лежат все прошлые и текущие версии.
2. Создается папка `/current/` - это симлинк, которая указывает на одну из папок внутри `/releases/`. Какой-нибудь [[Nginx]] настроен так, чтобы искать сайт только по пути `/current/`.
3. При [[CD (Continuous Delivery или Deployment)|CD]]-деплое [[CI CD раннер|раннер]] создает внутри папку, например, `/releases/v2/`, куда без спешки качает новую версию кода => пользователи сидят на v1 и не видят проблем в работе.
4. После тестов раннер выполняет в [[Терминал, Эмулятор терминала|терминале]] одну команду по созданию и перезаписи симлинка.
```bash
ln -sfn /releases/v2 /current
```
5. Команда выполняется на уровне [[Операционная система (ОС)|ОС]], после чего пользователи после обновления видят v2.
6. Старая папка не удаляется => при ролбэке выполняем обратную команду.
