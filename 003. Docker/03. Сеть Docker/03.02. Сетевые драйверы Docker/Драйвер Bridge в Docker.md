#flashcards/Docker 
***
Сетевой [[Драйвер|драйвер]] в [[Docker]] по умолчанию.
- При запуске [[Контейнер|контейнера]] какой-нибудь обычной командой по типу `docker run nginx` (вспоминаем про [[Nginx]]), Docker автоматически использует именно этот драйвер.
***
***Алгоритм работы.***
1. Мы активируем драйвер `bridge`, Docker обращается к [[Ядро операционной системы|ядру]] Linux, чтобы тот начал свою работу.
2. В системе создается [[Сетевой мост (Bridge)|сетевой мост]] - виртуальный [[Коммутатор (switch)|коммутатор]]. Это либо кастомный вариант (`br-символы`), либо дефолтный [[docker0]].
3. Для нового контейнера создается изолированная комната - network [[Пространства имен (namespaces)|namespace]], в которой нет Интернета.
4. Ядро Linux создает [[Virtual Ethernet Pair (Veth)|veth]]-кабель, после чего один конец втыкается в мост (ip link), второй - внутрь [[Песочница (Sandbox) Docker|песочницы]] через [[Конечная точка (Endpoint) в Docker|endpoint]].
5. После этого [[Встроенный IPAM в Docker|IPAM]] выделяет свободный [[IP-адрес]], который присваивается `eth0` внутри контейнера.
6. Сам мост получает первый адрес [[Подсеть|подсети]] (пример: `172.18.0.1`) - он становится [[Шлюз по умолчанию (Default Gateway)|шлюзом по умолчанию]].
7. Docker прописывает правила в ядро хоста о [[Network Address Translation (NAT)|NAT]], строит [[Межсетевой экран (Брандмауэр, Firewall)|Firewall]] и др. через [[Фреймворк Netfilter|Netfilter]].
***
***Активация.***
```bash
docker network create --driver bridge my_net
```
- Использована команда [[Network команда Docker|network]].
